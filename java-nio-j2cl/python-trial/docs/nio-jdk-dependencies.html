19 extra JDK types are enough for this compilation.

The generated NIO API references 58 external types. J2CL already supplies 41. The remaining 17, plus two required inheritance dependencies, are sufficient to transpile all 156 generated NIO source files.

This was checked with the actual J2CL compiler. The output file inventory and every file's contents match the existing build using 5,022 extra header classes.

What the compilation experiments established

Extra header typesResult
17 direct referencesFails: java.security.Permission missing.
17 + Permission = 18Fails: java.security.Guard missing.
17 + Permission + Guard = 19Passes. 156 Java sources and 171 JavaScript implementation modules. Every output file matches the original build, byte for byte.
19 + three temporal interfaces = 22Also passes, but the three extra interfaces are unnecessary for this compilation.

The three temporal interfaces are java.time.temporal.Temporal, TemporalAccessor, and TemporalAdjuster. They appear in Instant's inheritance hierarchy, but the NIO stub compilation succeeds without loading them. A full dependency closure would therefore overstate this particular build's requirements.

The selected 19-type header JAR is 30,413 bytes; the existing 5,022-type header JAR is 4,962,688 bytes. The normal Bazel build configuration is unchanged. This was an isolated analysis experiment.

Scope: these 19 declarations suffice for the current NIO stub transpilation. This is not a complete replacement JDK API or a browser runtime. Consumer code that uses other methods on these JDK types can need additional declarations and runtime implementations.

How the list was checked

  1. Ran JDK 17 jdeps --api-only -verbose:class -filter:none on the 163 compiled generated NIO types. This covers declarations, generic signatures, and inheritance.
  2. Compared external type names with the actual pinned J2CL core header JAR. This produced the 41 supplied / 17 missing split.
  3. Cross-checked against the separately extracted original JDK API. All 57 explicitly referenced external types matched; the compiled enum superclass java.lang.Enum accounts for the 58th.
  4. Ran ordinary jdeps as well: the throwing bodies add no external type names beyond that union.
  5. Selected existing declaration-only class files into reduced JARs, ran J2CL under the shared build lock, and compared the successful output with the baseline.

java.io.CharArrayReader is not in the 19-type set. The successful reduced build does not need its declaration.

# Validation evidence

All profile validation stages and the independent consumer passed on **2026-09-08**.
The compact recorded result is `compatibility/validation.json`.

The main profile passes **496 checks in optimized J2CL JavaScript in headless
Chromium**. This executes the emulation implementations, not the stock JVM's
concurrent classes. The bundle checksum and browser invocation result are recorded
in `out/browser/report.json`.

The checks exercise atomic state and overflow, snapshot collection iteration,
queue capacity and expiry, balanced lock ownership, unsatisfied wait boundaries,
real task execution, exception propagation, cancellation, executor hooks and
shutdown, pending/completed stages, a 10,000-stage chain, lazy ThreadLocal reset,
browser timers, periodic failure/cancellation and timer removal through queue APIs.

The 60 review regression checks cover losing race listener cleanup (including
cancellation and queued notifications), minimal-stage isolation against completion,
cancellation and obtrusion, mutation during map/view traversal, write-through
entries and conditional removal, and queue-aware shutdown/termination. A repeated
race probe uses 1,000 iterations against one pending input to detect retained
listeners. The independent consumer also exercises all four reviewed defects.

The unchanged JetBrains MPS `SimpleLRUCache` source is compiled and exercised for
canonicalization and eviction. `compatibility/mps-fixture.json` pins its source
revision and checksum, which the source guard verifies on each run. The MPS-style
generation-pool accounting and producer/completion-queue examples are focused
contract tests; they are not complete MPS subsystem builds.

`compatibility/api-coverage.json` confirms that the emitted JRE contains all **48
concurrency class names** identified by the MPS inventory, plus `Thread` and
`ThreadLocal` (**50/50**). Of those entries, 37 are provided by the overlay and 13
by stock J2CL. This check establishes type presence, not complete JDK method parity.

The independent consumer is generated by `tools/check_consumer.py`. It has its
own root `MODULE.bazel`, copies the generated patch into its own repository, and
checks the copy's SHA-256 before compilation and browser execution. Its evidence
is written to `out/consumer/patch-provenance.json` and
`out/consumer/browser/report.json`. This specifically tests Bazel's requirement
that root override patches belong to the consuming repository.
The independent consumer's optimized browser result is **PASS**; the generated
patch and its root-owned copy have identical SHA-256 values. Both task-owned Bazel
servers were stopped after validation.

Run `tools/validate.ps1` from PowerShell to reproduce the source/fixture guards,
patch consistency check, actual J2CL compilation, class-membership gate, browser
contracts and independent consumer check. WSL builds use the shared
`/tmp/j2cl-build.lock`, one Bazel job and one worker at a time. The script stops
only its own Bazel servers before moving between the two workspaces.

Full MPS module compilation, IntelliJ platform behavior, composed IO/NIO/WebAWT
overlays, arbitrary blocking loops, reflection and complete Java SE concurrency
semantics have not been validated. Those remain integration work.

## Historical plan and evidence

## Objective

Reach API completeness for the stock-J2CL WebAWT profile without claiming that browser-impossible or J2CL-impossible APIs work. Completeness means every feasible in-profile OpenJDK AWT type is emitted, every feasible member is callable with a compatible declaration, every callable member has behavior evidence appropriate to its implementation, and every remaining member is explicitly classified as unavailable or excluded with a precise reason.

Literal 325-type OpenJDK completeness is not the target. File dialogs and printing are excluded by scope, and APIs such as `Robot`, system tray integration, global pointer access, and blocking desktop event loops have no honest browser implementation. The completeness denominator must therefore be the audited stock-J2CL profile rather than the unfiltered OpenJDK inventory.

## Definition of done

WebAWT is stock-profile API complete only when all of these conditions hold:

1. No type or member remains `deferred`.
2. Every `exact`, `limited`, or `web-mapped` type is emitted by J2CL.
3. Every feasible member of those types resolves as an exact declaration, compatible declaration, or inherited declaration in the emitted jars.
4. Every omitted member is individually `unavailable` or `excluded`; an omitted member cannot inherit a broad type-level `limited` status by default.
5. No member is implemented as a silent no-op merely to satisfy the signature.
6. Every implemented member has a differential, J2CL, browser-contract, or compile-only test selected by an explicit test classification.
7. The emitted-API report has zero missing supported types, zero false implemented claims, zero supported declaration issues, and zero missing feasible members.
8. The complete JVM/J2CL suite, three-engine Playwright suite, optimized build, dependency gate, formatting gate, and bundle budgets pass.
9. Production still uses no runtime dependency beyond the pinned J2CL JRE and Elemental2 bindings.

## Per-slice execution protocol

Each implementation slice should contain one type, one tightly coupled type family, or one browser capability. A slice is not complete when only signatures compile.

1. Extract the exact OpenJDK public contract and J2CL signature dependencies.
2. Record exact, web-mapped, limited, unavailable, and excluded decisions at member level.
3. Write differential or browser-contract tests before promotion.
4. Implement the smallest dependency-free model and keep Elemental2 behind a narrow internal port.
5. Add J2CL compile/run coverage and an optimized-linkage test.
6. Add Playwright coverage when real DOM, Canvas, focus, input, permissions, or lifecycle behavior is involved.
7. Regenerate and inspect the emitted API report.
8. Run `Validate-WebAwt.ps1` and compare bundle-size changes.
9. Promote manifest state only after all evidence passes.

## Agent execution model

When parallel agent execution is requested, use four non-overlapping roles:

- The lead owns the manifest schema, shared Bazel targets, `Component`, integration, and final gates.
- The API auditor owns one milestone's reference signatures, J2CL feasibility, and member-level disposition without editing production implementations.
- The implementation agent owns a disjoint package or capability slice and its narrow internal interfaces.
- The test/review agent owns independent differential vectors, browser contracts, and parity review without rewriting the implementation under review.

Only disjoint packages should be edited concurrently. Shared files such as `Component`, `Window`, root test suites, compatibility generators, and common browser peers remain lead-owned. Each agent receives the audited member worklist rather than OpenJDK implementation bodies, preserving clean-room implementation and license provenance.

# MPS extensions runtime on J2CL

This workspace ports the runtime parts of grammar cells, query lists, the boolean
editor and the math editor, plus their editor hacks. It uses the MPS editor and
JRE implementation in the sibling `../mps-j2cl` workspace.

The upstream checkout is pinned at `3b2a1c4260c26e9692de48e32ef066db06cbe4fd`.
Upstream keeps its runtime implementations in MPS models, so Java is obtained
from the matching published source jars. The distribution URL, SHA256 and MPS
baseline are recorded in `source-lock.json`. No generation or edits take place
inside `mps-extensions/`.

## Layout

```text
mps-extensions-j2cl/
  mps-extensions/       pristine upstream Git checkout
  upstream-src/         pristine generated Java extracted from source jars
  j2cl-src/             changed Java and browser helpers, in package directories
  BUILD.bazel          runtime and browser verification targets
  MODULE.bazel         consumer-owned J2CL toolchain and local dependencies
  runtime-sources.bzl  explicit selected sources, generated by tools/inventory.py
  mps-access.json      MPS replacement paths and baseline hashes
  excluded-sources.json  desktop exclusions and reasons
  third_party/         composed J2CL patches copied from mps-j2cl
  tools/               bootstrap, source audit, build and browser checks
  tests/               behavioral tests using real MPS cells and model commands
  .work/mps-j2cl/      generated build view of the sibling project
  out/                 validation logs and reports
```

All Bazel metadata stays outside the upstream checkout. `j2cl-src` also contains
the eight MPS classes whose access modifiers change. The dependency view selects
these instead of the original classes, including the existing browser replacement
of `EditorComponent`; each type still has exactly one compiled provider. The
sibling workspace and its upstream MPS checkout remain unchanged.

## Bootstrap and validate

Use the same WSL Ubuntu, Java 21, Bazelisk, sibling repositories and Playwright
installation as `mps-j2cl`. Prepare the sibling workspace first using its bootstrap
instructions. Then, from PowerShell:

```powershell
wsl -d Ubuntu -- bash -lc 'cd /mnt/c/Codex/mps-extensions-j2cl && python3 tools/bootstrap.py'
wsl -d Ubuntu -- bash -lc 'cd /mnt/c/Codex/mps-extensions-j2cl && bash tools/validate.sh'
```

Builds share `/tmp/j2cl-build.lock` with the other projects and use one build job.
The first build in this workspace compiles the toolchain. Subsequent builds reuse
the workspace cache. Bootstrap refuses to reset a different or modified upstream
checkout and verifies the downloaded source archive before extracting it.

Public library targets are `//:grammarcells`, `//:querylist`, `//:boolean_editor`,
`//:math_editor`, `//:math_symbols`, `//:hacks`, `//:reflection` and `//:grammarcells_language`.
Applications can depend on `//:runtime`, which exports all eight libraries.
To compile individual libraries:

```bash
bash tools/bazel.sh build //:grammarcells //:grammarcells_language //:querylist //:boolean_editor //:math_editor //:math_symbols //:hacks //:reflection
```

`tools/validate.sh` additionally builds and runs development, optimized and
stripped-class-metadata contract bundles in Chromium, Firefox and WebKit. Results
include bundle hashes in `out/browser-results.json`; source ownership checks are
in `out/source-audit.json`. Test languages are handwritten fixtures, not a full
deployment of the extensions' language-design tooling or sandboxes.
The completed validation scope and results are recorded in [docs/validation.md](docs/validation.md).

## Browser integration

Use `mpsj2cl.editor.BrowserEditorHost` from the MPS dependency view for application,
model-access, rendering and editor lifecycle. Register compiled language runtimes
with its `BrowserPlatform` before editing their nodes.

Grammar descriptors are registered explicitly rather than loaded reflectively:

```java
host.getPlatform().registerLanguage(
    new com.mbeddr.mpsutil.grammarcells.runtimelang.Language());
GrammarCellsRuntime.init();
DescriptorCache.getInstance().register(
    language.getIdentity().getSourceModuleReference(),
    MyGrammarActionsDescriptor.INSTANCE);
```

Generated descriptor implementations remain ordinary compiled Java. Registration
invalidates grammar, editor-hierarchy and visible-language caches. Unregister a
descriptor when unloading its language; call `GrammarCellsRuntime.dispose()`
before disposing the application host. Cache invalidation preserves the compiled
registrations. Discovery uses language module references and does not require
desktop source-language modules in the repository.

The grammar runtime language includes the generated arbitrary-text annotation
editor. `GrammarCellsRuntime` installs its deletion/reparse handler and releases
the caches on disposal, replacing the desktop plugin lifecycle. Applications must
also register their compiled core language, including attribute structure and
behavior descriptors. The annotation editor uses the kernel's property-attribute
API; MPS behavior dispatch is retained and does not use Java reflection.

Specialized containment targets are resolved using compiled MPS structure
descriptors. This removes the dependency on the language-design structure behavior
code. The grammar cursor uses an explicit copy in place of `Object.clone()`, and
the editor-hierarchy overload delegates correctly to its version accepting hints.
Deleting the last arbitrary-text annotation from a model root now preserves the
root instead of trying to reparse a null subtree.

For generated conditional editor wrappers, call
`EditorHierachyCache.getInstance().registerConditionalEditor(MyConditionalEditor.class)`
at application startup. The desktop implementation recognizes these by a class-name
substring; the browser uses explicit class identities so stripped metadata works.
Unregister them when unloading the language; `GrammarCellsRuntime.dispose()` clears
all wrapper registrations.

If the full math language runtime is absent, register
`new de.itemis.mps.editor.math.runtime.MathRuntimeLanguage()` before constructing
math cells. It supplies the two original style attributes, including the original
spelling `side-tranformation-helper-cells`, and their defaults. Do not register it
alongside the full math language; both have the same language identity. It supplies
only the runtime style aspect, not the math language-design editors or generator.
The `math_symbols` target includes all 26 upstream built-in symbol implementations,
including sums, integrals, products, parentheses and brackets.

Boolean cells retain the upstream image-loading behavior and default vector
checkbox drawing. Custom images require browser-accessible resources through the
MPS/WebAWT resource mechanism; desktop filesystem image paths require a separate
browser storage backend.

## Static reflection routes

`de.slisson.mps.reflection.runtime.ReflectionUtil` keeps the generated call-site
API but dispatches only the reviewed operations to statically referenced MPS
members. It uses class identity, not class-name metadata, for dispatch.

| MPS member exposed as public | Runtime use |
| --- | --- |
| `UpdaterImpl.myBigCellsMap` | Query-list cell tracking |
| `SubstituteMenuItemAsActionItem.mySubstituteItem` | Wrapper substitution output concept |
| `EditorComponent.myEditorComponentActions` | Cursor tracker lookup |
| `EditorComponentActions` and `myActionMap` | Cursor tracker lookup |
| `NodeEditorActions.MoveDown.myPositionTracker` | Math navigation |
| `EditorCell_Label.getUpdatedText(String)` | Math end-cell input |
| `EditorCell_STHint.myAnchorCell` | Grammar side transformations |
| `CellAction_InsertIntoCollection.myListHandler` | Insert action role lookup |

Existing final modifiers remain intact. Unregistered fields, methods, signatures,
class names and writes throw `UnsupportedOperationException`. No generic Java
reflection or reflective final-field writes are emulated. Grammar descriptor
singletons use registration instead of a dynamic `INSTANCE` field read.

## Excluded scope

The explicit exclusions in `excluded-sources.json` cover desktop IntelliJ plugin
registration, model-checker actions, keymap integration and popup infrastructure.
The parser timeout notification interface and non-popup insert-action helpers are
retained. `EditorComponentHacks` retains Swing component traversal and excludes
the IntelliJ `JBTabs` branch. Lightweight color and input helpers already supported
by `mps-j2cl` remain dependencies.

Language generators, language-design editors, sandbox languages, IDE installation
and arbitrary additional reflection hacks are outside this runtime profile.
